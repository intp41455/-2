# 02 · 变体与设计风格体系

本项目的核心设计决策是：**「给谁看」和「长什么样」是两个正交的维度，各自独立配置。**

---

## 为什么要拆成两个维度

如果把它们揉在一起（「高管版」= 高管内容 + 咨询风格），会出现两种浪费：

1. 想给高管看技术风格版 → 必须再造一个组合
2. 风格迭代要动内容配置 → 改一处影响一片

拆开后：

```
      5 种变体（内容裁剪）
  ×   6 种风格（视觉呈现）
  ────────────────────────
  =  30 种输出形态     ← 底层内容零重复
```

实现上两者互不感知：变体只影响**哪些 `<section>` 渲染**，风格只影响**容器 class 与版式骨架**。

---

## 变体（`DOCUMENT_VARIANTS`）

定义于 `src/data/variantsData.ts`。

### 配置结构

```ts
export interface DocumentVariantConfig {
  id: DocumentVariantId;        // 'full' | 'executive' | 'questionnaire' | 'technical' | 'audit_case'
  name: string;                 // 显示名
  tag: string;                  // 一句话定位标签
  badge: string;                // 徽标文案
  coverTitle: string;           // 封面主标题 ← 随变体切换
  coverSubtitle: string;        // 封面副标题
  targetAudience: string;       // 目标读者（同时进 Markdown 题注）
  estimatedPages: string;       // 预估篇幅
  accentColor: string;          // 强调色
  sections: string[];           // ★ 章节白名单——变体的核心机制
  description: string;          // 内容导读（进 Markdown 摘要）
  recommendedFileName: string;  // 建议导出文件名
}
```

### 五个变体

| ID | 名称 | 目标读者 | `sections` | 篇幅 |
|---|---|---|---|---|
| `full` | 全景综合完整版 | 集团高管、技术总监、数字化办公室、外部评审专家 | `1,2,3,4,5,6` | 16-20 页 |
| `executive` | 管理决策战略版 | 董事长、总裁、总经理办公会、投资人与战略决策委员会 | `1,3,4` | 6-8 页 |
| `questionnaire` | 业务调研 SOP 问卷版 | 人力资源部、财务部、各院区负责人、IT 信息中心 | `6` | 5-6 页 |
| `technical` | 技术工程与安全版 | 研发 / 架构 / 安全团队 | `1,2,3,4,5` | 10-12 页 |
| `audit_case` | 康源智脑实战与持续审计版 | 行业评审、监察合规 | `1,4,5` | 8-10 页 |

### 裁剪机制

`DocumentBody.tsx` 中的判定：

```ts
const isSectionVisible = (sectionId: string) => {
  return currentConfig.sections.includes(sectionId);
};
```

每个 `<section>` 外层包一层条件渲染：

```tsx
{isSectionVisible('section-1') && (
  <section id="section-1" className={...}>
```

`TableOfContents` 用同一份白名单过滤目录条目：

```ts
const filteredSections = TOC_SECTIONS.filter(sec => variant.sections.includes(sec.id));
```

→ **目录与正文永远一致**，不会出现「目录列了但正文没渲染」。

### 切换变体时的联动

`App.tsx` 里 `onSelectVariant` 会同时把 `showAllSections` 复位为 `false`：

```tsx
onSelectVariant={(v) => {
  setCurrentVariant(v);
  setShowAllSections(false);
}}
```

避免在「展开全部」状态下切变体造成状态错乱。

## 设计风格（`DESIGN_VARIATIONS`）

同文件定义，共 6 套。

### 六套风格

| ID | 名称 | 底色 / 强调色 | 字体特征 | 版式 |
|---|---|---|---|---|
| `variation-7` | 建筑典雅出版风 | `#F8F7F4` / 赭石 `#CC5500` | Cormorant Garamond 衬线大标题 + Space Mono 架构微标 | 双栏 + 侧栏 |
| `variation-1` | 暖白出版研报风 | `#FDFBFA` / 焦糖 `#CC5500` | 炭焙黑字阶 `#2D2824` | 居中单栏（2:1 研报网格） |
| `variation-2` | 瑞士结构网格风 | 纯白 / 深色描边 | 包豪斯国际主义网格 + 等宽编号 | 居中单栏 |
| `variation-3` | 现代白底双栏工作台 | `slate-50` / indigo | 树状目录 + 白卡片 | 双栏 + 侧栏 |
| `variation-4` | 咨询战略简报风 | `#FAFAFA` / 深海蓝 | 麦肯锡 / BCG 白皮书质感 | 居中单栏（圆角卡片） |
| `variation-5` | 现代科技简约风 | `#F9FAFB` / indigo | 指标 Hero 看板 + 微标体系 | 双栏 + 侧栏 |

### 版式分流

风格不复制内容，只决定**外层容器 class** 与**走哪个布局分支**：

```ts
// 1) 容器底色 / 字色 / 选中色
const getContainerClasses = () => {
  switch (currentDesign) {
    case 'variation-7': return 'min-h-screen bg-[#F8F7F4] text-[#1C1C1A] ...';
    case 'variation-1': return 'min-h-screen bg-[#FDFBFA] text-[#2D2824] ...';
    // ...
  }
};

// 2) 是否双栏（决定渲染路径）
const isTwoColumnLayout =
  currentDesign === 'variation-7' ||
  currentDesign === 'variation-5' ||
  currentDesign === 'variation-3';
```

- **双栏分支**（v7 / v5 / v3）：`SidebarNav` 左侧固定章节导航 + 右侧主内容流；v7 与 v5 额外渲染 `EditorialHero` 指标看板
- **单栏分支**（v1 / v2 / v4）：`max-w-[1020px]` 居中阅读流，外层按风格施加不同边框 / 圆角 / 内边距

### 切换反馈

切风格时 `App.tsx` 会置 `showDesignNotice = true`，顶栏下方弹出可关闭的提示条：

> 当前设计风格变体：**{名称}**（{tag}）。— 您可在顶栏随时自由切换全部 5 种历史设计风格。

## 扩展方式

### 新增一个变体

1. 在 `src/types.ts` 的 `DocumentVariantId` 联合类型里加 ID
2. 在 `DOCUMENT_VARIANTS` 里补齐配置对象（必须提供全部字段，含 `recommendedFileName`）
3. 无需改任何组件——顶栏选择器遍历 `Object.values(DOCUMENT_VARIANTS)` 自动出现

### 新增一套风格

1. 在 `src/types.ts` 的 `DesignVariationId` 里加 ID
2. 在 `DESIGN_VARIATIONS` 里补齐配置
3. 在 `App.tsx` 的 `getContainerClasses()` 里加一个 `case`
4. 若要双栏版式，同时加进 `isTwoColumnLayout` 判定

## 已知边界

| 项 | 说明 |
|---|---|
| `variation-4` 的 `getContainerClasses` 分支存在，但 `variation-4` 不在 `isTwoColumnLayout` 中——走单栏分支 |
| `variation-5` 在 switch 里与 `default` 共用返回值，因其底色与默认值相同 |
| `DocumentVariantId` 在 `types.ts` 与 `variantsData.ts` 中各声明了一次（后者是局部重复声明）。两处若不一致，以 `types.ts` 为准——建议后续统一为单一来源 |

### 待修：风格数量文案不一致（文案 bug）

`App.tsx` 的风格切换提示条写的是：

> — 您可在顶栏随时自由切换全部 **5 种**历史设计风格。

但 `DESIGN_VARIATIONS` 实际有 **6 套**（`variation-7` / `1` / `2` / `3` / `4` / `5`）。

**影响**：仅文案层面，功能正常。**修复位置**：`src/App.tsx` 中 `showDesignNotice` 提示条内的 `<span className="hidden md:inline ...">`。
