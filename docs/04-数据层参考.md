# 04 · 数据层参考

`src/data/` 是**内容的单一真源**。组件与三个导出器都从这里取数。

设计原则：**数据层只放有结构的内容**（条目、字段、评分、公式），叙述性文案仍留在正文组件里。

## `auditData.ts`

### `AUDIT_TIERS: AuditTier[]`

```ts
interface AuditTier {
  tierNumber: number;       // 1 / 2 / 3
  name: string;             // 层级名（含英文原名）
  stage: string;            // 触发时机
  purpose: string;          // 目的
  coreMechanism: string;    // 核心机制
  passStandard: string;     // 合格标准（可量化）
  actionItems: string[];    // 待办动作
}
```

**三层各自的合格标准（可量化，这是这套设计最有价值的部分）**：

| 层级 | 合格标准摘要 |
|---|---|
| 1 · Pre-Launch 数字孪生沙盘 | 常规场景一致性 **≥ 95%**，且 5% 极端边缘场景**均被安全拦截**并触发人工兜底预案，方可进入下一开发阶段 |
| 2 · Runtime 三明治交叉验证 | 见源码 `passStandard` |
| 3 · Post-Run 周期复盘 | 见源码 `passStandard` |

层级 1 的 `coreMechanism` 细节：抽取过去 6 个月真实运营与考勤脱敏数据，人工构造 **50+ 极端边界案例**（入住率骤降至 50%、节假日排班真空、三机构同时更换院长等），监察 Agent 在封闭沙箱中模拟执行，比对 AI 裁决与人类历史处理结果。

### `INCIDENT_RESPONSE_MATRIX`

```ts
{
  level: string;              // 'L1 - 轻微异常 (Minor Alert)' 等
  trigger: string;            // 触发条件
  responseAction: string;     // 系统响应
  humanIntervention: string;  // 人工介入要求
  badgeColor: string;         // UI 徽标 class
}
```

| 级别 | 触发条件 | 系统响应 | 人工介入 |
|---|---|---|---|
| **L1** 轻微异常 | 单家分支机构单日某一非关键字段缺失（如某日日照中心餐食满意度未及时同步） | 记录异常审计日志，向本院信息对接人推送轻度催办，次日凌晨自动重试，**不中断主流程** | 无需人工接管，自愈或顺延重试 |
| **L2** 一般异常 | Agent 输出格式损坏、字段与 Schema 不符，或明显内部勾稽矛盾（如**实发工资环比突变 > 20%**） | 立即挂起该子 Agent 工作流，自动重试 1 次；仍异常则**阻断向下一节点推送**，并邮件 + 企微告警至技术主管与业务主管 | 需业务主管登录管理看板查看差额明细，点击「人工确认放行」或「驳回重新计算」 |
| **L3** 严重致命异常 | 连续 3 天机构核心数据中断、多 Agent 输出严重逻辑悖论、**检测到疑似提示词注入攻击或越权操作指令** | **全面触发物理熔断**：Orchestrator 立即封锁所有对外 API，冻结本地写入脚本，系统回退至只读状态，触发紧急安全警报 | 见源码 `humanIntervention` |

### `KANGYUAN_AGENTS: AgentRoleDefinition[]`（4 个）

```ts
interface AgentRoleDefinition {
  id: string;
  name: string;                 // 中文名 + 英文名
  title: string;                // 一句话职能定位

  color: string;
  responsibilities: string[];   // 职责
  inputs: string[];             // 输入
  outputs: string[];            // 输出
  strictConstraints: string[];  // 硬性约束
  systemPromptSnippet: string;  // ★ 可直接复制到生产的提示词片段
}
```

| 角色 | 职能 | 映射岗位 | 模型 |
|---|---|---|---|
| 运营数据聚合师 (Operations Aggregator) | 多机构多源异构数据实时规整智能体 | 数据中台分析主管 | DeepSeek-V3 / Qwen-2.5-72B |
| 标准合规审计员 (Standards Auditor) | 213 项康源美宏标准机器核验智能体 | 质控审计 | 见源码 |
| 人才培训辅助师 (Education & Training AI) | 订单班与在岗技能个性化智训智能体 | 培训主管 | 见源码 |
| 智慧决策顾问 (Strategic Advisor) | 政策感知与扩张投资智慧参谋智能体 | 战略投资 | 见源码 |

`modelRationale` 示例（运营数据聚合师）：*处理中文长文本、复杂 Excel 表格及 AIoT 设备时序日志能力优越，极具性价比*。

### `PAYROLL_FORMULAS`（6 项）

```ts
{ name: string; formula: string; desc: string; }
```

| 名称 | 公式 | 说明 |
|---|---|---|
| 法定日薪换算 | `日薪 = 底薪 ÷ 21.75` | 依据劳动法标准计薪月天数折算，精确到分 |
| 事假扣减规则 | `事假扣款 = 事假天数 × 日薪 × 100%` | 全额扣减无薪事假工时 |
| 病假薪酬保障 | `病假扣款 = 病假天数 × 日薪 × 40%` | 合规保障病假按 60% 日薪标准计发 |
| 迟到阶梯扣款 | `1~15分钟: 20元；16~60分钟: 50元；>60分钟: 扣半天日薪` | 阶梯式约束 |
| 旷工惩罚机制 | `旷工扣款 = 旷工天数 × 日薪 × 3` | 严厉遏制无故缺勤与未审批脱岗 |
| 五险一金代扣 | `五险一金 = 缴费基数 × (社保个人比例 10.5% + 公积金比例 12%)` | 税前统筹扣减项目 |

> ⚠️ **这些公式是文档示范值，不是法律意见**。任何实际使用前必须由企业 HR / 法务按其所在地政策核准。

## `questionnaireData.ts`

### `QUESTIONNAIRE_SECTIONS: QuestionnaireSection[]`（10 部分 / 22 采集项）

```ts
interface QuestionnaireSection {
  id: string;
  partNumber: string;              // '第一部分'
  title: string;
  description: string;
  questions: {
    key: string;                   // 唯一键
    question: string;              // 问题
    instruction: string;           // 填写说明（口径 / 精度）
    kangyuanExample: string;       // ★ 康源真实填报示范
  }[];
}
```

`kangyuanExample` 是本问卷最实用的设计——**每一问都给一个真实填好的例子**，填报人不用猜「这题到底要写到什么颗粒度」。

### `QUESTIONNAIRE_WORKFLOW_STEPS`（6 步）

```ts
{ step: string; title: string; desc: string; icon: string; }
```

| 步 | 标题 | 说明 |
|---|---|---|
| 01 | 问卷发放 | 方案立项前 1-2 周，由总架构师下发问卷至企业 |
| 02 | 指定协调人 | 企业指定项目负责人，负责统筹内部各业务口 |
| 03 | 业务分头填报 | 机构运营、财务、质控、人事分头填写对应章节 |
| 04 | 统一汇总格式化 | 协调人整理脱敏附件、消除矛盾项与口径分歧 |
| 05 | 内部审签与盖章 | 分管领导审核确认，签署保密知悉与真实性承诺 |
| 06 | 交付方案策划 | 架构团队基于精准输入，定制 100% 可落地方案 |

> `icon` 字段存的是 **lucide-react 图标名字符串**，消费端需做名称到组件的映射。

## 维护约定

1. **数字只在 `data/` 出现一次**。正文里若需要引用，走变量而非硬编码。
2. **新增数据条目后检查一致性**。例如 `standardsBreakdown` 四项之和必须等于 `standardsCount`。
3. **`strictConstraints` / `systemPromptSnippet` 是要交付给生产系统的字段**，改动前确认语义，不要当成展示文案随手改。
4. **对外分发前评估密级**——`caseStudyData.ts` 全量含真实企业业务指标。
