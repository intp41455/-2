## 总体结构

正文承载在 `src/components/DocumentBody.tsx`，由 6 个 `<section id="section-N">` 组成；目录元数据定义在 `src/components/TableOfContents.tsx` 的 `TOC_SECTIONS`。

```
section-1  序言与核心安全哲学          ── 立论：为什么不能直接给模型"手"
section-2  薪资考勤自动化精算体系        ── 验证：最高幻觉代价场景的完整解法
section-3  框架横评与混合架构选型        ── 工具：怎么选、怎么混
section-4  康源智脑标杆实战             ── 案例：真实企业怎么落
section-5  3-Tier 审计体系              ── 兜底：怎么持续证明它没跑偏
section-6  10 维度信息采集标准问卷       ── 前置：做方案之前先要什么数据
```

**论证逻辑是一条链**：先立「模型不能有执行权」的论（第 1 章）→ 用最容易出事、也最容易验证的场景把论跑通（第 2 章）→ 给工具选型（第 3 章）→ 给真实企业落地样本（第 4 章）→ 给持续监督机制（第 5 章）→ 最后给一份「动手之前先把这些问清楚」的调研问卷（第 6 章）。

## 第 1 章 · 序言与核心安全哲学

> 章节标题：AI 本质与不可逆执行风险

| 子节 | 要点 |
|---|---|
| 1.1 模型失控与沙盒逃逸的法理剖析 | LLM 本质是基于概率统计的**非确定性续写引擎**。把「写权限 / 数据库删除权限 / 资金划拨权限」交给模型自主调用时，不可逆风险随调用链条长度**指数级上升** |
| 1.2「左移确定性」铁律 | 运行期加护栏是无效的——概率型算法的输出**不可枚举**，你无法穷举所有拦截条件。正确做法是把确定性向左移动到工程前期：业务制度 → 人工梳理核准 → 刚性规则库（JSON Schema / 状态机）→ 模型只做一次「自然语言 → 结构化」翻译 → 本地死代码执行 |
| 1.3 双门模型 | **第一道门：内容护栏**（管模型的「嘴」，控制权在服务商云端）；**第二道门：执行护栏**（管操作系统的「手」，控制权在本地部署者）。关键风险点在第二道门：模型返回合法 JSON 时第一道门会判定通过，真正的越权风险来自本地代码是否写了 `os.system(模型输出)` |
| 1.4 架构师角色演进 | 领域架构师的崛起——价值从「会调 API」转向「能把业务制度翻译成机器可执行的刚性规则」 |

**治理铁律（原文表述）**：永远把模型当「输入法」（只提建议值），不当「操作系统」（不给直接系统指令权限）。所有文件写入与网络请求，必须经过本地写死的白名单。

## 第 2 章 · 多智能体薪资考勤自动化精算体系

选择薪资考勤作为验证场景，原因是它同时具备两个属性：**幻觉代价最高**（算错钱涉及劳动关系）且**结果最易验证**（对错一眼看出）。

| 子节 | 要点 |
|---|---|
| 2.1 钉钉考勤文本与数据口径映射 | 非结构化考勤文本（打卡记录、请假审批、补卡单）→ 数据口径的映射规则 |
| 2.2 三大核心智能体岗位定义 | **需求解析师**（把非结构化文本抽取为 JSON）/ **精算执行员**（本地算子，确定性计算）/ **审计监察员**（独立第三方核验）。每个岗位有独立的 `systemPromptSnippet`、输入、输出与 `strictConstraints` |
| 2.3 刚性算法公式池与四则运算隔离 | 公式池共 **6 项**：法定日薪换算 / 事假扣减规则 / 病假薪酬保障 / 迟到阶梯扣款 / 旷工惩罚机制 / 五险一金代扣，全部写死于代码 |
| 2.4 零幻觉生产级 Python 隔离执行脚本 | 约 20 行的隔离执行示范：模型只输出结构化参数，金额由本地四则运算产出 |

**核心约束**：模型可以输出 `{"name":"张三","事假":1}`，**不可以**输出「张三实发 5758.62 元」——后者必须由本地脚本按写死的四则运算算出，即使模型算对了也不采纳，因为**无法验证它下次是否还这么算**。

数据来源：`src/data/payrollData.ts`（`PAYROLL_AGENTS` / `PAYROLL_FORMULAS`）。

## 第 3 章 · 主流智能体框架深度横评与混合架构选型

| CrewAI | 开发框架 | 像导演组建剧组——基于「角色扮演」的多智能体敏捷协作 | 职责清晰、需快速打样验证的敏捷团队 | 中（基础代码） | 8 / 8 / 9 |
| LangGraph | 开发框架 | 像程序员绘制精细状态流转图——基于「有向循环图」的工业级编排底座 | 金融、医疗、财务等要求确定性、状态回滚、断点续跑的生产环境 | 高（全代码） | 10 / 9 / 6 |
| Dify / 扣子 (Coze) | 低代码平台 | 像搭乐高积木——拖拽式画布与可视化全功能工作流平台 | 产品经理、业务骨干主导的内部管理流程 | 零 / 极低代码 | 7 / 7 / 10 |
| Hermes / OpenClaw | 自主智能体 | 像聘用全能个人助理——长程持久记忆 + 自动化调用工具的自主底座 | 极客个人工作流自动化、自托管研发助手、环境探针 | 高（全代码） | 5 / 4 / 7 |
| 腾讯 WorkBuddy（专家团） | 企业级应用 | 像开箱即用的 AI 专家智囊团——内置百种行业专家角色的桌面端数字员工 | 依托腾讯会议 / 企微生态的中大型企业办公协同 | 零 / 极低代码 | 7 / 8 / 9 |
| Harness | DevOps 平台 | 像严谨的发布质检官——嵌入 CI/CD 的 AI 代码审查与安全门禁 | 大型研发团队的交付管线、PR 合规审查与漏洞修复 | 高（全代码） | 9 / 10 / 7 |

### 3.3 黄金三角混合部署架构（`HYBRID_DEPLOYMENT_PILLARS`）

| 支柱 | 内容 |
|---|---|
| **本地核心骨架（安全底线）** | 敏感核心数据（员工薪资、老人健康档案、财务凭证）100% 保留在企业私有容器内，**物理不出域**。由本地开源小模型（DeepSeek / Qwen-7B/14B）或死代码负责日常清洗和私有计算 |
| **云端智能插件（能力上限）** | 需要理解国家新政、长篇法律条文或高难度数学证明时，通过**智能路由器**将完全去隐私化的抽象文本抛给云端前沿大模型，仅返回结论文本——既保密又聪明 |
| **精细化规则引擎（核心壁垒）** | 把企业所有「奇葩个性化规则」（如哺乳期打卡宽容、异地调休系数）用 JSON Schema 写死在确定性工作流中。大厂通用产品永远不会为你微调，这构成企业不可替代的数字护城河 |

| 层级 | 名称 | 触发时机 | 目的 |
|---|---|---|---|
| 层级 1 | 方案落地前审计：数字孪生沙盘推演 (Pre-Launch Sandbox) | 正式进入生产环境编码前 | 在耗费昂贵工程人力前，用历史真实数据与极端地雷场景验证方案拓扑是否会「跑飞」 |
| 层级 2 | 运行中实时监控：「三明治」交叉验证 (Runtime Sandwich Check) | 生产环境每次任务流转时实时触发 | 在数据从上游 Agent 传递至下游 Agent 的**毫秒级窗口**内进行阻断式校验，不让脏数据污染全局 |
| 层级 3 | 周期性复盘审计：反馈闭环与自进化 (Periodic Review & Feedback Loop) | 每月例行总结 + 每季度战略复盘 | 评估 AI 系统实际商业产出，消除误报与死板规则，推动知识库和底层模型迭代 |

每一层在源码中携带 `coreMechanism` / `passStandard` / `actionItems`——即「怎么做 / 什么算合格 / 不合格怎么办」。

## 维护约定

1. **改文案优先改 `data/`**，不要直接改 `DocumentBody.tsx` 里的硬编码文字——只有结构性新增才动组件。
2. **新增章节需三处同步**：`DocumentBody.tsx` 加 `<section>` + `TOC_SECTIONS` 登记 + 目标变体的 `sections` 白名单加 ID。
3. **数字必须可溯源**。第 4 章的所有指标都来自 `KANGYUAN_METRICS`，不要在正文里散写数字。
4. **对外分发前评估密级**。第 4 章含真实企业业务指标。
