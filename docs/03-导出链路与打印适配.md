# 03 · 导出链路与打印适配

三路导出全部是**纯前端**实现，无服务端参与。全部代码在 `src/utils/`。

---

## 导出器总览

| 导出器 | 函数 | 产物 | 摘要 |
|---|---|---|---|
| `htmlExporter.ts` | `generatePrintableHtml(variantId)` | 离线单文件 HTML（**打印优化版**） | 内联全部样式 + 全部内容数据 + **可运行的原生 JS 仿真沙盘**。约 52 KB 源码 |
| `htmlExporter.ts` | `generateWysiwygHtml(variantId)` | 离线单文件 HTML（**所见即所得版**） | 还原当前风格版式，含独立的 `@page` 规则（`12mm 14mm`） |
| `htmlExporter.ts` | `openPrintableTab(variantId, autoDownload?)` | 新窗口 / 触发下载 | 打印通道 + 沙箱 iframe 规避方案 |
| `markdownExporter.ts` | `generateVariantMarkdown(variantId)` | `.md` 文本 | 按变体章节白名单裁剪，带版本 / 受众 / 密级题注 |
| `markdownExporter.ts` | `downloadFile(content, filename, mimeType)` | 通用下载 | `Blob` + `URL.createObjectURL` + 临时 `<a>` |

> `generatePrintableHtml` 的两份 HTML 各自带完整的 `<style>` 与 `@page` 规则，**不依赖任何外部资源**——断网、无 CSS 框架、无字体 CDN 也能正常渲染与打印。

## 为什么需要 `openPrintableTab`

这是本项目最容易踩的坑：

```text
在 Google AI Studio 预览里，应用运行在 <iframe> 中。
浏览器出于安全策略，会拦截 iframe 内的 window.print()。
→ 表现：点打印按钮没反应，或抛出静默异常。
```

`App.tsx` 的处理逻辑：

```ts
const handleConfirmPrint = () => {
  const inIframe = window.self !== window.top;
  if (inIframe) {
    // 已确认处于 iframe 内 → 直接走新窗口通道，不做无谓的 print() 尝试
    openPrintableTab(currentVariant, true);
  } else {
    try {
      window.print();
    } catch (err) {
      openPrintableTab(currentVariant, true);   // 兜底
    }
  }
};
```

**关键点**：先探测 `window.self !== window.top` 再决定路径，而不是「先试 print、失败再兜底」——因为 iframe 内的 `print()` 可能是**静默失败**（不抛异常、无提示），兜底逻辑永远触发不了。

## 打印样式（`src/index.css`）

```css
@media print {
  .no-print { display: none !important; }      /* 顶栏 / 侧栏 / 浮动按钮 / 提示条 / 页脚 */
  .print-only { display: block !important; }

  body {
    background-color: #ffffff !important;
    color: #0f172a !important;
    font-size: 10.5pt;                          /* 打印基准字号 */
    line-height: 1.5;
    margin: 0 !important; padding: 0 !important;
  }

  /* 强制保留背景色与边框（否则深色块会变成白底） */
  * {
    -webkit-print-color-adjust: exact !important;
    print-color-adjust: exact !important;
  }

  @page {
    size: A4 portrait;
    margin: 12mm 14mm 12mm 14mm;
  }

  .pdf-page-break   { page-break-after: always !important; break-after: page !important; }
  .pdf-avoid-break  { page-break-inside: avoid !important; break-inside: avoid !important; }
}
```

### 相关 class 的使用位置

| class | 作用 | 用在哪 |
|---|---|---|
| `no-print` | 打印时隐藏 | `Header` / `SidebarNav` / 返回顶部按钮 / 设计风格提示条 / 应用页脚 / `InteractivePlayground` 的控制按钮 / `CoverPage` 的操作按钮区 / `DocumentBody` 的搜索提示条 |
| `pdf-page-break` | 该元素后强制分页 | 六个 `<section>`——**仅在 `viewMode === 'paged'` 时施加**：`${isPaged ? 'pdf-page-break' : ''}` |
| `pdf-avoid-break` | 元素内禁止断页 | 图表 / 表格块 |
| `pdf-container` | 打印容器标识 | `#printable-document` |

> **只有 `paged` 视图会施加分页 class**。这是有意的：连续视图导出长文档时不需要在每章之间硬插分页。

## Markdown 导出

`generateVariantMarkdown(variantId)` 读取 `DOCUMENT_VARIANTS` 拿到变体配置，再按 `variant.sections` 逐章拼接。

文件头模板：

```markdown
# {coverTitle}
## {coverSubtitle}

> **版本**: V2.6.4 | **适用受众**: {targetAudience} | **日期**: 2026年9月 | **密级**: 内部商业机密

---

### 【{variant.name} · 内容导读】

{variant.description}

---
```

**注意**：Markdown 导出器**没有直接复用 React 组件**，而是把每章正文以模板字符串重新写了一遍（`src/utils/markdownExporter.ts` 约 11 KB）。

这是当前架构的一个**真实成本**：正文改动需要同步两处。见下方「维护提示」。

## 离线 HTML 里的内嵌沙盘

`generatePrintableHtml` 生成的 HTML 内嵌了一份**原生 JavaScript 版**的仿真沙盘（`<script>` 段，约第 877–1061 行），与 React 组件 `InteractivePlayground` 功能对应但实现独立。

数据形态是「预计算好的结果」而非「实时计算」：

```js
var PRESET_CASES = [
  {
    name: "张三 (事假1天 + 正常出勤)",
    base: 8000,
    text: "张三本月应出勤22天，打卡记录均在08:50前完成……",
    parsed: { "员工姓名": "张三", "事假天数": 1, "病假天数": 0, "迟到次数": 0, "旷工天数": 0, "全勤状态": false },
    risk: "P3 建议级",
    verdict: "合规放行 (PASS)",
    verdictClass: "verdict-pass",
    detail: "事假1天已在OA报备扣除，未触发薪资异常波动警戒线。"
  },
  // 李四 → P2 预警扣减 (WARN)
  // 王五 → 严重异常
  // 赵六 → 全勤
];
```

**为什么这么做**：离线文件的定位是「发给别人自己看的成品」，不需要可维护性，需要的是**零依赖、零构建、双击即用**。把计算结果预先烘进去最符合这个目标。

## 维护提示（重要）

当前「同一份内容存在于多处」，改动时需同步：

| 内容 | 存在位置 |
|---|---|
| 六个章节正文 | ① `components/DocumentBody.tsx` ② `utils/htmlExporter.ts` ③ `utils/markdownExporter.ts` |
| 沙盘 4 组用例 | ① `components/InteractivePlayground.tsx` ② `utils/htmlExporter.ts` 的内嵌脚本 |
| 康源指标 / 框架横评 / 问卷数据 | `data/` 单点定义，被 ①②③ 共同引用 ✅ |

**数据层（`data/`）是单点真源，这部分没有重复问题**——重复只发生在「叙述性文案」上。

若后续正文迭代频繁，建议的收敛方向是：让 `htmlExporter` / `markdownExporter` 只消费 `data/` + 结构化描述，不再手写叙述段落。

## 推荐导出路径

| 想要 | 走法 |
|---|---|
| 屏幕阅读 | 直接用 `paged` 或 `continuous` 视图 |
| 干净 A4 PDF | 导出**离线单文件 HTML** → 浏览器打开 → `Ctrl+P` → 边距「默认」+ 勾选「背景图形」 |
| 发给别人自己翻 | 离线单文件 HTML（含可交互沙盘） |
| 灌进别的知识库 | Markdown 导出 |
| 交给设计改版 | 离线 HTML + 本文档第 02 篇（变体与风格配置说明） |
